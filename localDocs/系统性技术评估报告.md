## 1. 性能问题分析

### 1.1 响应时间基准测试

| 指标         | 当前状态             | 基准目标 | 评估      |
| ------------ | -------------------- | -------- | --------- |
| 计算响应时间 | < 100ms (Worker模式) | < 200ms  | ✅ 达标   |
| 页面加载时间 | 依赖legacy数据加载   | < 3s     | ⚠️ 需优化 |
| 图标加载     | 事件驱动+超时保护    | < 2s     | ✅ 已优化 |

### 1.2 已识别的性能优化点

**✅ 已实现的优化：**

- Web Worker 非阻塞计算（`src/core/services/CalculatorService.ts`）
- 状态快照验证机制，避免无效计算
- 图标加载事件驱动替代轮询（`src/App.vue`）
- 设置变更防抖（100ms）

**⚠️ 潜在瓶颈：**

1. **遗留数据加载等待**：`waitForLegacyData` 最大等待10秒，可能阻塞首屏渲染
2. **配方索引构建**：`recipeIndexByProduct` 在主线程构建，大数据量时可能卡顿
3. **蓝图生成内存占用**：BlueprintService 生成大量建筑对象时内存峰值较高

### 1.3 资源利用率评估

```
CPU使用模式：
├── 主线程：UI渲染 + 状态管理 + 数据同步
├── Worker线程：配方计算（已迁移）
└── 潜在问题：legacy数据加载仍阻塞主线程

内存使用模式：
├── 配方数据：~2MB (recipes.json + 索引)
├── 图标数据：~5MB (Base64编码)
└── 蓝图生成：临时对象峰值 ~10MB
```

## 3. 时序问题分析

### 3.1 组件交互时序验证

**关键时序链：**

```
用户操作 → App.vue → Store.addDemand()
    → Store.watch触发 → syncStateToLegacy()
    → App.vue:await nextTick() → syncStateToLegacy()（手动同步）
    → CalculatorService.calculateWithOptions()
    → Worker.calculate() / 主线程计算
    → 结果返回 → Store.setResultItems()
```

### 3.2 已修复的时序问题

| 问题 | 修复版本         | 位置             | 描述                                       |
| ---- | ---------------- | ---------------- | ------------------------------------------ |
| P5-1 | value2计算时序   | UpdateAllService | value2必须在checkResult之前计算            |
| P6-1 | 临界光子修正时序 | UpdateAllService | fixCriticalPhotonSpeed必须在loadNumber之前 |
| P0-3 | doSpeed1时序     | UpdateAllService | 轨道采集器t值缓存必须在loadNumber之前      |
| P2-1 | 图标加载时序     | App.vue          | 事件驱动替代轮询                           |

### 3.3 潜在竞态条件

**⚠️ 已识别风险：**

1. **Worker初始化竞态**（`CalculatorWorkerService.ts`）：

   ```typescript
   // 风险：Worker可能在init完成前收到calculate请求
   if (this.status !== 'ready') {
     throw new Error(`Worker not ready (status: ${this.status})`)
   }
   ```

   - **缓解措施**：calculate方法内部会调用init等待
   - **建议**：添加init状态队列，避免并发init调用

2. **状态快照验证失败重试**（`App.vue`）：
   ```typescript
   if (error instanceof StateChangedDuringCalculationError && retryCount < 3) {
     // 重试逻辑
   }
   ```

   - **评估**：最多重试3次，已足够处理正常场景
   - **建议**：添加重试计数监控，便于问题排查

### 4.3 异常处理机制评估

**异常处理架构：**

```
全局错误边界
    └── ErrorBoundary.vue
        └── 捕获组件渲染错误

服务层异常
    ├── CalculatorService
    │   ├── StateChangedDuringCalculationError (可重试)
    │   └── 配方数据未初始化错误
    └── UpdateAllService
        └── 计算超时/递归深度超限

Worker异常
    └── CalculatorWorkerService
        ├── Worker初始化失败 → 降级到主线程
        └── 计算超时 → 返回错误
```

**⚠️ 需要增强的异常处理：**

1. **蓝图生成异常**：BlueprintService 异常直接抛出，建议添加更详细的错误信息
2. **数据验证异常**：BlueprintAdapter 验证失败时错误信息较笼统
