# 网站工程化完善实施计划（按优先级执行）

版本：v1.3  
日期：2026-03-21  
适用项目：DSQ（静态前端工具站）

## 1. 目标与执行原则

本计划用于将当前"功能成熟的工具站"逐步提升为"可持续维护的成熟网站工程"。

**新增目标**：
- 部署到 Vercel 平台
- 实现多语言支持（i18n）
- 搜索引擎优化（SEO）
- 可访问性合规（a11y）
- Core Web Vitals 性能优化

执行原则：

1. 先托底再重构：先补齐工程化基础（质量门禁、CI、测试底座、监控），再做代码结构拆分。
2. 小步快跑：每一步都可独立验证、可回滚、可发布。
3. 不中断业务：核心计算与蓝图功能在全程保持可用。
4. 以验收结果为导向：每个任务必须有明确产出物与验收标准。

## 3. 阶段A（P0）详细计划：先保稳定与协作效率

## A-01 建立 Node 工程脚手架（最高优先）

- 目标：统一脚本入口，消除"手工执行"不一致。
- 具体动作：

1. 新增 `package.json`（脚本只做工程编排，不改业务运行形态）。
2. 增加 npm scripts：`lint`、`format:check`、`smoke`、`ci:check`。
3. 锁定 Node 版本（`.nvmrc` 或 `engines` 字段）。

- 产出物：`package.json`、锁版本说明文档。
- 验收标准：`npm run ci:check` 本地可一次通过。
- 预计工时：0.5-1 天。
- 依赖：无。
- 完成状态：✅ 已完成（2026-03-19）

## A-02 接入 ESLint + Prettier（并先以低风险策略上线）

- 目标：统一代码风格与基础质量规则，降低未来重构冲突。
- 具体动作：

1. 新增 ESLint 与 Prettier 配置。
2. 第一阶段采用"增量约束"策略：旧代码允许 warning，新改代码严格。
3. 对新增文件开启严格 lint；历史大文件分批治理。

- 产出物：`eslint.config.js`（ESLint 9 flat config）、`.prettierrc`、`.prettierignore`。
- 验收标准：`npm run lint` 可稳定运行并输出可读结果。
- 预计工时：1-1.5 天。
- 依赖：A-01。
- 完成状态：✅ 已完成（2026-03-20）

## A-03 配置 Git Hooks 质量门禁（pre-commit / pre-push）

- 目标：在提交前阻断明显问题，减少坏代码进入主分支。
- 具体动作：

1. 配置 `.husky/pre-commit`：执行 `lint-staged`（或最小 lint 检查）。
2. 配置 `.husky/pre-push`：执行 `npm run ci:check` 或最小 smoke。
3. 添加失败提示文案，便于团队成员快速定位问题。

- 产出物：`.husky/pre-commit`、`.husky/pre-push`、`lint-staged` 配置。
- 验收标准：

1. 提交含错误代码会被拦截。
2. 正常提交流程耗时可接受（建议 < 60 秒）。

- 预计工时：0.5-1 天。
- 依赖：A-01、A-02。
- 完成状态：✅ 已完成（2026-03-21）

## A-04 建立最小 CI（自动执行质量检查）

- 验收标准：

## 4. 阶段B（P1）详细计划：可维护性与可测试性

1. `state`：状态对象与读写。
2. `calc-core`：纯计算逻辑。
3. `ui-bindings`：DOM 与事件绑定。
4. `storage`：localStorage/cookie 读写。
5. `bootstrap`：初始化流程。

- 产出物：新模块目录与迁移说明。
- 验收标准：拆分前后关键功能行为一致（人工回归 + 测试）。
- 预计工时：3-5 天。
- 依赖：阶段A完成。
- 完成状态：🟡 部分完成（2026-03-21）
- 当前结果：
  1. 已将 `calc-core` 独立为 `Scripts/calc-core.js`，并由 `data.js` 调用。
  2. 已将 `storage` 能力拆分为 `Scripts/data.storage.js`（设置读写函数迁移）。
  3. 已将 `bootstrap` 能力拆分为 `Scripts/data.bootstrap.js`（页面初始化链路迁移）。

- 当前结果：
  1. 已将蓝图常量区抽离为 `Scripts/blueprint.constants.js`。
  2. `Scripts/blueprint.js` 已改为消费外部常量，`worker` 链路已同步加载常量文件。
- 剩余差距：
  1. `model/layout/serializer` 尚未完成独立分层与文件化。
  2. 蓝图核心流程仍集中在单文件 class 中，改动风险仍偏高。

## 6. 阶段D（P2）详细计划：网站化能力建设（新增）

## D-01 国际化（i18n）实现

- 目标：支持多语言，扩大用户覆盖范围。
- 具体动作：

1. 集成 vue-i18n 或类似国际化库。
2. 提取所有 UI 文本到语言资源文件（zh-CN, en-US 等）。
3. 实现语言切换功能（UI 组件 + localStorage 持久化）。
4. 配置多语言 SEO（hreflang 标签）。
5. 实现多语言 URL 结构（可选：/en/, /zh/）。
6. 处理数字、日期、货币的本地化格式。

- 产出物：
  - `locales/` 目录（语言资源文件）
  - i18n 配置模块
  - 语言切换组件
  - 多语言 SEO 配置

- 验收标准：
  1. 支持至少 2 种语言（中文、英文）。
  2. 语言切换后所有 UI 文本正确显示。
  3. 刷新页面后语言设置保持。
  4. hreflang 标签正确配置。

- 预计工时：3-5 天。
- 依赖：阶段B完成。

## D-02 Core Web Vitals 优化

- 目标：达到 Google 2025 年性能基准，提升用户体验和搜索排名。
- 具体动作：

1. **LCP 优化**：
   - 优化关键渲染路径。
   - 预加载关键资源（preload/prefetch）。
   - 优化字体加载（font-display: swap）。
   - 考虑使用 CDN 加速资源加载。

2. **INP 优化**（替代 FID）：
   - 优化长任务（拆分、延迟执行）。
   - 使用 Web Worker 处理复杂计算。
   - 减少主线程阻塞。

3. **CLS 优化**：
   - 为图片设置明确尺寸。
   - 预留动态内容空间。
   - 避免在现有内容上方插入内容。

4. 接入 Lighthouse CI 进行持续监控。

- 产出物：性能优化配置、Lighthouse CI 配置。
- 验收标准：
  1. LCP < 2.5 秒。
  2. INP < 200ms。
  3. CLS < 0.1。
  4. Lighthouse Performance 得分 > 85。

- 预计工时：3-4 天。
- 依赖：C-01（构建体系）。

## D-03 高级 SEO 优化

- 目标：进一步提升搜索可见性和社交分享效果。
- 具体动作：

1. 实现动态 Meta 标签（根据页面状态更新）。
2. 添加面包屑导航结构化数据。
3. 优化图片 SEO（alt 属性、图片 sitemap）。
4. 实现规范链接（canonical URL）管理。
5. 添加 FAQ 结构化数据（如有适用内容）。
6. 配置 Google Search Console 和 Bing Webmaster Tools。

- 产出物：高级 SEO 配置、结构化数据模板。
- 验收标准：
  1. Lighthouse SEO 得分 = 100。
  2. Google Search Console 无严重错误。
  3. 富媒体搜索结果正常显示。

- 预计工时：2-3 天。
- 依赖：B-05。

## D-04 高级可访问性优化

- 目标：达到 WCAG 2.1 AA 级合规。

## 10. 风险与应对


| 风险            | 表现      | 应对策略             |
| ------------- | ------- | ---------------- |
| 旧代码 lint 报错过多 | 首次接入阻力大 | 采用增量治理，不一次性清历史债务 |
| 拆分引发行为回归      | 结果计算偏差  | 先补测试，再拆模块，保留回归样例 |
| CI 过慢影响效率     | 提交等待时间长 | 分层执行：快速检查与完整检查分离 |
| 监控噪音太大        | 告警泛滥    | 先定义核心指标与阈值，再扩展维度 |
| i18n 文本提取遗漏   | 部分文本未翻译 | 建立文本提取脚本，定期扫描硬编码 |
| SEO 效果不明显     | 排名提升慢   | 持续优化内容质量，增加外链建设 |
| 性能优化效果不稳定    | 指标波动大   | 建立 Lighthouse CI 持续监控 |
