## 1. 目标与执行原则

本计划用于将当前"功能成熟的工具站"逐步提升为"可持续维护的成熟网站工程"。

**新增目标**：

- 部署到 Vercel 平台
- 实现多语言支持（i18n）
- 搜索引擎优化（SEO）
- 可访问性合规（a11y）
- Core Web Vitals 性能优化

执行原则：

1. 先托底再重构：先补齐工程化基础（质量门禁、CI、测试底座、监控），再做代码结构拆分。
2. 小步快跑：每一步都可独立验证、可回滚、可发布。
3. 不中断业务：核心计算与蓝图功能在全程保持可用。
4. 以验收结果为导向：每个任务必须有明确产出物与验收标准。

## 3. 阶段A（P0）详细计划：先保稳定与协作效率

## A-01 建立 Node 工程脚手架（最高优先）

- 目标：统一脚本入口，消除"手工执行"不一致。
- 具体动作：

3. 锁定 Node 版本（`.nvmrc` 或 `engines` 字段）。

- 具体动作：

1. 新增 ESLint 与 Prettier 配置。
2. 第一阶段采用"增量约束"策略：旧代码允许 warning，新改代码严格。

## 10. 风险与应对

| 风险                 | 表现           | 应对策略                         |
| -------------------- | -------------- | -------------------------------- |
| 旧代码 lint 报错过多 | 首次接入阻力大 | 采用增量治理，不一次性清历史债务 |

| 监控噪音太大         | 告警泛滥       | 先定义核心指标与阈值，再扩展维度 |
| i18n 文本提取遗漏    | 部分文本未翻译 | 建立文本提取脚本，定期扫描硬编码 |
| SEO 效果不明显       | 排名提升慢     | 持续优化内容质量，增加外链建设   |
| 性能优化效果不稳定   | 指标波动大     | 建立 Lighthouse CI 持续监控      |

### 16.3 新增专项说明（2026-03-25）

#### E-13：`#UIselector` 可访问性收敛

现状缺口：

1. 对话框缺少 `role="dialog"`、`aria-modal`、标题关联等语义。
2. 打开后未自动聚焦首个可操作项；关闭后未回到触发按钮。
3. 缺焦点陷阱与 `Esc` 关闭，Tab 可逃逸到背景层。
4. 图标网格主要为 `div + click`，缺键盘触发语义（Enter/Space）。

建议验收：

1. 键盘路径可闭环：`打开 -> Tab/方向键选择 -> Enter 确认 -> Esc/选择后关闭 -> 焦点回退`。
2. E2E 新增键盘用例与 a11y 审计断言，纳入 `ci:check`。

#### E-14：`#MoreSetting` 开合体验优化

现状缺口：

1. 采用 `show/hide + setTimeout`，存在跳变与时序不同步风险。
2. `btnSetting` 缺 `aria-expanded` / `aria-controls` 状态同步。
3. 缺 reduced-motion 特化策略，弱网/低性能设备下开合观感生硬。

建议验收：

1. 开合动画平滑、状态一致，不再依赖 magic number 延迟。
2. `aria-expanded` 与面板可见状态保持一致。
3. `prefers-reduced-motion` 下提供无动画或弱动画分支。
