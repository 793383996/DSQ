# 网站工程化完善实施计划（按优先级执行）

版本：v1.14  
日期：2026-03-24  
适用项目：DSQ（静态前端工具站）

## 1. 目标与执行原则

本计划用于将当前"功能成熟的工具站"逐步提升为"可持续维护的成熟网站工程"。

**新增目标**：

- 部署到 Vercel 平台
- 实现多语言支持（i18n）
- 搜索引擎优化（SEO）
- 可访问性合规（a11y）
- Core Web Vitals 性能优化

执行原则：

1. 先托底再重构：先补齐工程化基础（质量门禁、CI、测试底座、监控），再做代码结构拆分。
2. 小步快跑：每一步都可独立验证、可回滚、可发布。
3. 不中断业务：核心计算与蓝图功能在全程保持可用。
4. 以验收结果为导向：每个任务必须有明确产出物与验收标准。

## 15. 商业成熟度差距详析（2026-03-24）

### 15.1 结论摘要

当前项目已从“纯功能工具站”升级到“具备基础工程化能力的可持续项目”，但距离“成熟商业网站”仍存在关键缺口。  
综合成熟度评估：**约 6.3 / 10**（可稳定迭代，但尚未达到商业化长期运营标准）。

### 15.2 维度评分与差距矩阵

| 维度 | 当前状态 | 证据（仓库现状） | 与成熟商业网站的差距 | 优先级 |
| ---- | -------- | ---------------- | -------------------- | ------ |

| 商业合规与运营 | 2.5/10 | 当前主要为技术治理文档 | 缺隐私政策、条款、Cookie 说明、SLA/应急预案 | P0 |

### 15.3 与成熟商业网站的关键缺口（按紧急度）

1. 发布主链路未收敛：`dist` 与 `dist-vite` 并存，生产仍未切到 Vite，导致缓存策略与构建能力无法完全释放。  
2. CSP 无法上线：`index.html` 仍存在较多内联事件与 `javascript:` 链接，阻塞严格安全头落地。  
3. 第三方依赖治理不完整：jQuery/Vue 等以静态文件形式维护，无法通过 npm 安全工具形成全量漏洞视图。  
4. 监控仍处“可发送”而非“可运营”状态：缺统一平台、告警策略、值班流程、版本维度诊断。  
5. 性能无持续预算：尚未形成 CWV 量化目标的自动化采集与回归门禁。  
6. 商业化合规资产不足：缺隐私政策、服务条款、Cookie/数据说明、漏洞披露与安全响应文档。  
7. 多语言与全球化能力缺失：尚未具备 i18n 资源抽取、切换和多语言 SEO 能力。  
8. 研发治理文档老化：`README` 与当前工程化状态不一致，外部协作与新成员上手成本偏高。

### 15.4 商业化“可上线”最低门槛（建议）

1. 构建发布统一到 Vite 主链路，具备可回滚方案。  
2. CSP 可在生产环境启用（至少 Report-Only 到 Enforce 的可执行路径）。  
3. 监控平台落地并具备关键告警（错误率、蓝图失败率、P95 耗时）。  
4. CWV 与 Lighthouse 建立基线并接入 CI 门禁。  
5. 隐私政策/条款/安全披露流程等基础合规文档上线。  
6. B-02 收尾完成，核心引擎复杂度继续下降。

### 17.3 建议执行策略（低风险）

1. 采用“双轨并行 + 分段切流”策略：先保留旧入口，按模块迁移后逐段切换。
2. 每完成一个迁移模块必须通过：`test:unit`、`test:e2e`、`test:integration`、`ci:check`。
3. 每个 V 任务都要求有“回退开关”或“兼容适配层”，避免一次性不可逆切换。

### 17.4 完成判定（Vue 完整迁移）

1. 生产入口以 Vue SFC 为主（无历史脚本拼装依赖）。
2. jQuery 与内联脚本从主链路移除。
3. 核心链路（新增需求/修改配置/生成蓝图）在新架构下回归通过。
4. 文档、监控、发布与回滚流程全部对齐新架构。
