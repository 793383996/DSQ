### 1.2 状态机模式

#### CalculationStore 状态机

```typescript
export enum CalcState {
  IDLE = 'idle', // 空闲
  PREPARING = 'preparing', // 准备数据
  CALCULATING = 'calculating', // 计算中
  SUCCESS = 'success', // 成功
  ERROR = 'error' // 错误
}

const transitions: Record<CalcState, CalcState[]> = {
  [CalcState.IDLE]: [CalcState.PREPARING],
  [CalcState.PREPARING]: [CalcState.CALCULATING, CalcState.ERROR],
  [CalcState.CALCULATING]: [CalcState.SUCCESS, CalcState.ERROR],
  [CalcState.SUCCESS]: [CalcState.IDLE, CalcState.PREPARING],
  [CalcState.ERROR]: [CalcState.IDLE, CalcState.PREPARING]
}
```

## 三、潜在问题排查

### 3.1 性能问题排查

#### ✅ 已解决：死代码问题

- **位置**：`BootstrapService.ts`（已删除）
- **问题**：约300行未使用的初始化编排代码
- **修复**：已删除
- **影响**：减少打包体积，提高加载速度

#### ✅ 已解决：watch 触发链优化

- **位置**：`demand.ts`, `settings.ts`
- **问题**：初始化时 watch 触发不必要的同步和持久化
- **修复**：添加 `isInitializing` 标记
- **影响**：减少初始化时的不必要操作

#### ✅ 已解决：localStorage 同步写入

- **位置**：`demand.ts`, `settings.ts`
- **问题**：localStorage.setItem() 是同步阻塞操作
- **修复**：添加 debounce 机制（100ms），避免频繁写入阻塞主线程
- **影响**：提高性能，减少主线程阻塞

#### 🟡 需关注：JSON.stringify 性能

- **位置**：多处 localStorage 操作
- **问题**：频繁的 JSON.stringify 可能影响性能
- **影响**：大数据量时序列化耗时增加
- **建议**：考虑使用更高效的序列化方案或增量更新

#### 🟡 需关注：watch deep 选项

- **位置**：`demand.ts:192`, `settings.ts:174`
- **问题**：`deep: true` 会递归遍历所有属性
- **影响**：大型对象时性能下降
- **建议**：考虑使用 shallowRef 或精确指定监听属性

### 3.2 流程问题排查

#### ✅ 已解决：状态同步方向不明确

- **位置**：`demand.ts`, `App.vue`
- **问题**：初始化时双向同步导致循环
- **修复**：
  - 添加 `loadFromLegacy()` 方法实现单向加载
  - 添加 `isInitializing` 标记防止初始化时同步
- **影响**：明确数据流向，避免循环同步

#### ✅ 已解决：错误恢复不完整

- **位置**：`LegacyDataService.ts`
- **问题**：初始化失败后无法重试
- **修复**：
  - 初始化失败时自动调用 `reset()`
  - 添加 `reinitialize()` 方法支持重新初始化
- **影响**：提高系统健壮性

#### ✅ 已解决：设置变更回调管理

- **位置**：`blueprint.ts`
- **问题**：`settingsChangeCallbacks` 未使用
- **修复**：删除死代码，委托给 `settingsStore.onSettingsChange()`
- **影响**：代码更清晰

#### 🟢 良好：事件监听器清理

- **位置**：`App.vue:200-220`
- **问题**：`gameDataLoaded` 事件监听器在超时时可能未清理
- **分析**：当前实现已在超时回调中清理监听器
- **状态**：无需修改

#### ✅ 已解决：设置变更双重触发

- **位置**：`settings.ts`, `blueprint.ts`
- **问题**：`watch` 和方法都会触发 `notifySettingsChange()`
- **修复**：
  - 移除 `settings.ts` watch 中的 `notifySettingsChange()` 调用
  - 移除 `blueprint.ts` 中多余的 `notifySettingsChange()` 调用
- **影响**：避免设置变更时回调被重复触发

### 3.3 时序问题排查

#### ✅ 已解决：竞态条件 - 同步顺序

- **位置**：`demand.ts:forceSyncToLegacy()`
- **问题**：同步过程中状态可能被修改
- **修复**：
  - 添加 `isSyncing` 标记
  - 使用 Promise 队列确保同步完成
  - 添加 `pendingSyncResolve` 处理等待情况
- **影响**：确保同步操作完整性

#### ✅ 已解决：竞态条件 - 配方索引就绪

- **位置**：`bridge.ts:getRecipeIndexReadyPromise()`
- **问题**：Promise 可能在 notify 调用前创建，导致竞态
- **修复**：在函数开始时检查 `recipeIndexReady` 状态，如果已就绪直接返回 resolved Promise
- **影响**：避免竞态条件

#### 🟢 良好：初始化超时处理

- **位置**：`InitializationService.ts`
- **问题**：初始化可能无限等待
- **分析**：当前实现使用 `APP_CONFIG.TIMEOUTS` 统一配置超时
- **状态**：无需修改

#### ✅ 已解决：计算重试时序问题

- **位置**：`App.vue`
- **问题**：重试期间用户可继续操作导致状态变化
- **修复**：移除重试时的状态重置，保持 `isCalculating = true` 防止用户操作
- **影响**：确保重试期间状态一致性

### 3.4 逻辑漏洞排查

#### ✅ 已解决：状态机转换不完整

- **位置**：`calculation.ts`
- **问题**：`setCalculating()` 未检查当前状态

#### ✅ 已解决：快照验证不严格

- **分析**：当前实现支持状态快照和验证

```typescript
/**
 * 注册设置变更监听器
 *
 * 重要：调用方必须在组件销毁时调用返回的清理函数，否则会导致内存泄漏
 *
 * @example
 * // 在 Vue 组件中使用
 * const cleanup = settingsStore.onSettingsChange(() => { ... })
 * onUnmounted(() => cleanup())
 *
 * @param callback 设置变更时调用的回调函数
 * @returns 清理函数，调用后移除该监听器

function onSettingsChange(callback: () => void): () => void {

  return () => settingsChangeCallbacks.delete(callback)
```
