## 1. 堆叠功能概述

建筑堆叠将一条平铺的产线蓝图，垂直复制到多个 z 层（z=0, 10, 20, 30），使相同产能占用更小的地表面积。

```
核心设计思想：

┌─────────────────────────────────────────────────────────────────────────────┐
│                          堆叠流程完整调用链                                  │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  BlueprintService.generate()                                                │
│  ├── 1. adjustRecipesForStackLayers() - Phase 1: num缩减                   │
│  │   └── 非Lab设备: num = ceil(num / stackLayers)                          │
│  │   └── Lab设备: num保持不变                                               │
│  │                                                                          │
│  ├── 2. generateBuildings() - Phase 2: 单层布局                            │
│  │   └── BuildingGeneratorFactory.generateSingleBuilding()                 │
│  │   └── Lab垂直堆叠: z=0,3,6,9 (由maxLabLayers控制)                        │
│  │   └── 其他设备: z=0 单层布局                                             │
│  │                                                                          │
│  ├── 3. ItemSummaryCalculator.calculate() - Phase 3: rate计算              │
│  │   └── applyStackLayers(): rate *= stackLayers                           │
│  │   └── applyStackLayersToSorters(): sorter.rate *= stackLayers           │
│  │                                                                          │
│  ├── 4. generateConveyors() - Phase 3: 传送带生成                          │
│  │   └── ConveyorGenerator.generateConveyorBelts()                         │
│  │   └── z=0传送带按总产能设计                                              │
│  │                                                                          │
│  └── 5. cloneToStackLayers() - Phase 4: 克隆到高层                         │
│      └── 生成地基: z=-10, 0, 10, 20                                        │
│      └── 克隆建筑: z=10, 20, 30                                            │
│      └── 过滤: Lab/传送带/喷涂机不克隆                                      │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘

### 详细流程说明：

**Phase 1: adjustRecipesForStackLayers() - num缩减**
```

输入: stackLayers=4, 设备num=60, Lab num=4
处理: 非Lab设备 num = ceil(60/4) = 15
Lab num = 4 (保持不变)
代码: BlueprintService.adjustRecipesForStackLayers()

```

**Phase 2: generateBuildings() - 单层布局**
```

z=0 层布局:

- 15 设备 + 15 分拣器
- 4 Lab (垂直堆叠 z=0,3,6,9，由LabGenerator处理)
- Lab 分拣器
  代码: BlueprintService.generateSubRecipeBuildings()
  → BuildingGeneratorFactory.generateSingleBuilding()

```

**Phase 3: ItemSummaryCalculator + generateConveyors() - rate放大**
```

itemSummary.rate _= stackLayers (支撑所有层总产能)
sorters.rate _= stackLayers
sortersPerNode = floor(max/stackLayers)
z=0传送带汇聚所有层产物，按总产能设计
代码: ItemSummaryCalculator.applyStackLayers()
ItemSummaryCalculator.applyStackLayersToSorters()

```

**Phase 4: cloneToStackLayers() - 克隆到高层**
```

1. 记录 z=0 层全部建筑
2. 生成地基 (每层独立): z=-10, 0, 10, 20
3. 过滤可克隆建筑 (排除Lab/传送带/喷涂机)
4. 逐层克隆 + index 重映射
   → 15设备 × 3份 → z=10,20,30
   → 15分拣器 × 3份 → z=10,20,30
   代码: BlueprintService.cloneToStackLayers()

```

**共享传送带网络**
```

所有层的分拣器连接到z=0的传送带
z=0传送带支撑所有层总产能
4层并行工作，总产能 = 单层 × stackLayers

```

```

## 5. Index 重映射机制

```
index 引用重映射规则：

1. outputObjIdx（分拣器输出目标）：
   - 克隆分拣器 → 同层克隆设备（通过 indexMap）
   - 克隆分拣器 → z=0 传送带（保持原值）

2. inputObjIdx（设备输入源）：
   - 克隆设备 → 该层对应的地基
     layer=1 → z=10 设备 → z=0 地基 (foundationStartIndex + 1)
     layer=2 → z=20 设备 → z=10 地基 (foundationStartIndex + 2)
   - 克隆分拣器 → 同层克隆设备（通过 indexMap）

3. 共享传送带网络：
   - 所有层的分拣器 outputObjIdx 指向 z=0 的传送带
   - 这样 4 层都连接到同一套传送带网络
```

## 13. 设计决策记录

### 13.1 indexMap 按层存储

**问题**：克隆多层建筑时，如何追踪每层的索引映射？

**决策**：使用 `Map<number, Map<number, number>>` 结构，外层 Map 的 key 为层号，内层 Map 为该层的索引映射。

**原因**：

- 便于调试时查看每层的映射关系
- 支持后续可能的跨层引用场景
- 与原 blueprint.js 的实现保持一致

### 13.2 深拷贝策略

**问题**：克隆建筑时，如何处理 `parameters` 和 `yaw` 等引用类型属性？

**决策**：使用 `JSON.parse(JSON.stringify())` 进行深拷贝，或使用 `.slice()` 复制数组。

**原因**：

- 避免克隆建筑与原建筑共享引用
- 测试用例验证了修改克隆不会影响原建筑

### 13.3 边界校验和自动修正

**问题**：用户传入无效配置时如何处理？

**决策**：在构造函数中进行校验，无效值自动修正为默认值，并输出警告日志。

**原因**：

- 提高服务健壮性
- 避免因配置错误导致的运行时异常
- 便于调试和问题定位
