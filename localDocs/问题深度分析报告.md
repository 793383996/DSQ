### 1.1 双重状态同步

#### 具体表现形式

#### 特征分析

| 维度       | 老代码                     | 新架构                  | 差异说明               |
| ---------- | -------------------------- | ----------------------- | ---------------------- |

#### 根因分析

#### 影响评估

- **性能影响**：轻微（两次同步操作耗时 < 1ms）
- **逻辑影响**：无（两次同步结果一致）
- **维护成本**：中等（需要理解双重同步的设计意图）

#### ✅ 修复方案（2026-02-20实施）

**修复策略**：统一同步入口 + 版本追踪机制

#### ✅ 修复方案（2026-02-20实施）

**修复策略**：延迟转换 + 按需缓存

**问题根因**：

- `RecipeAdapter.loadFromRawData()` 使用 `rawData.map(transformRecipe)` **全量复制**了配方数据
- 但实际查询方法使用的是**复用的索引**，转换后的数据仅在索引构建时使用
- `UpdateAllService` 直接引用 `window.data`，没有复制

**修复内容** ([RecipeAdapter.ts](file:///d:/Android/Project/DSQ/src/core/adapters/RecipeAdapter.ts))：

```typescript
// 修复前：全量复制
this.recipes = rawData.map((item, idx) => this.transformRecipe(item, idx))
// 内存增加: ~2MB

// 修复后：延迟转换 + 按需缓存
private rawRecipes: IRawRecipe[] = []  // 引用原始数据
private recipeCache: Map<number, IRecipe> = new Map()  // 按需缓存

loadFromRawData(rawData: IRawRecipe[]): void {
  this.rawRecipes = rawData  // 直接引用，不复制
  this.reuseExistingIndex()
}

private getRecipe(idx: number): IRecipe | null {
  const cached = this.recipeCache.get(idx)
  if (cached) return cached

  const recipe = this.transformRecipe(this.rawRecipes[idx], idx)
  this.recipeCache.set(idx, recipe)  // 按需缓存
  return recipe
}
```

**修复效果**：

- ✅ 消除配方数据全量复制，节省约2MB内存
- ✅ 使用延迟转换，仅在首次访问时转换配方
- ✅ 缓存机制确保同一配方不会重复转换
- ✅ 保持API兼容性，不影响现有调用方

## 3. 已识别风险深度评估

### 3.1 Worker初始化竞态

#### 触发条件

**场景1：并发init调用**

```typescript
// CalculatorWorkerService.ts:93-118
async init(options): Promise<void> {
  if (this.status === 'ready') return

  // 风险：多个calculate调用可能同时进入init
  if (this.initPromise) return this.initPromise

  this.initPromise = new Promise((resolve, reject) => {
    // ...
  })
}
```

**场景2：init未完成时调用calculate**

```typescript
async calculate(options): Promise<IWorkerResult> {
  if (this.status !== 'ready') {
    throw new Error(`Worker not ready (status: ${this.status})`)
  }
}
```

#### 后果分析

| 触发场景        | 直接后果     | 最终影响         |
| --------------- | ------------ | ---------------- |
| 并发init        | 重复初始化   | 资源浪费         |
| init中calculate | 抛出异常     | 降级到主线程计算 |
| init超时        | Worker不可用 | 持续降级         |

#### 缓解措施评估

**当前措施**：

```typescript
// initPromise复用机制
if (this.initPromise) return this.initPromise
```

**评估结果**：

- ✅ 防止并发init
- ⚠️ calculate仍可能在init完成前被调用
- ❌ 无pending请求队列

#### ✅ 修复方案（2026-02-20实施）

**问题根因**：`isAvailable()` 与 `calculate()` 状态检查不一致

| 检查点         | `isAvailable()` | `calculate()` | 结果 |
| -------------- | --------------- | ------------- | ---- |
| `idle`         | ✅ true         | ❌ 抛异常     | 降级 |
| `initializing` | ✅ true         | ❌ 抛异常     | 降级 |
| `ready`        | ✅ true         | ✅ 执行       | 正常 |

**核心矛盾**：`isAvailable()`认为`initializing`可用，但`calculate()`不接受该状态。

**修复策略**：移除冗余的状态检查，利用已有的`init()`等待机制

**修复内容** ([CalculatorWorkerService.ts](file:///d:/Android/Project/DSQ/src/core/workers/CalculatorWorkerService.ts))：

```typescript
// 修复前：calculate()中检查状态，导致竞态

  if (this.status === 'error') {
    throw new Error('Worker not available')
  }

  if (this.status !== 'ready') {  // ← 问题：initializing时抛异常
    throw new Error(`Worker not ready (status: ${this.status})`)
  }
  // ...
}

// 修复后：移除冗余检查，利用init()的等待机制
async calculate(options: IWorkerCalculateOptions): Promise<IWorkerResult> {
  if (this.status === 'error') {
    throw new Error('Worker not available')
  }
  // 移除了 this.status !== 'ready' 检查
  // init()方法已有initPromise等待机制，会自动等待初始化完成
  // ...
}
```

**修复效果**：

- ✅ 消除竞态条件，`calculate()`会等待`init()`完成
- ✅ 利用现有的`initPromise`机制，无需额外队列
- ✅ 简化代码逻辑，减少维护成本

**改进建议**：

```typescript
// 建议：添加pendingCalculationQueue
private pendingQueue: Array<{
  resolve: (result: IWorkerResult) => void
  reject: (error: Error) => void
  options: IWorkerCalculateOptions
}> = []

async calculate(options): Promise<IWorkerResult> {
  if (this.status !== 'ready') {
    return new Promise((resolve, reject) => {
      this.pendingQueue.push({ resolve, reject, options })
    })
  }
  // ...
}

private processPendingQueue(): void {
  while (this.pendingQueue.length > 0 && this.status === 'ready') {
    const { resolve, reject, options } = this.pendingQueue.shift()!
    this.calculate(options).then(resolve).catch(reject)
  }
}
```

- ✅ 高频操作场景下重试成功率提升

```typescript
  this.adaptiveDelay = Math.min(100, this.adaptiveDelay * 2)

  // 监控告警
  if (this.retryCount > 2) {
    logger.warn(`[App] High retry count: ${this.retryCount}`)
  }
}
```
