# DSP 工厂规划器 - 架构迁移方案

## 0. 迁移原则：架构师红线

* **零停机迁移**：每个阶段完成后，应用必须可正常运行。
* **增量替换**：新代码通过适配层与旧代码共存，逐步替换。
* **回滚能力**：每个阶段完成后打 Git Tag，确保可随时回退。
* **测试先行**：核心业务逻辑必须有 Baseline 测试覆盖。

## 6. 性能基准

### 6.1 关键指标

| 指标 | 当前值 | 目标值 | 测量方法 |
|------|--------|--------|----------|
| 首屏加载时间 | ~500ms | <300ms | Lighthouse |
| 计算耗时 (100项) | ~50ms | <30ms | Performance API |
| 蓝图生成 (500建筑) | ~100ms | <50ms | Performance API |
| 内存占用 | ~50MB | <30MB | Chrome DevTools |

### 6.2 性能监控

```typescript
// src/utils/performance.ts
export function measurePerformance<T>(
  name: string,
  fn: () => T
): T {
  const start = performance.now()
  const result = fn()
  const duration = performance.now() - start
  
  if (duration > 16) { // 超过一帧
    console.warn(`[Performance] ${name} took ${duration.toFixed(2)}ms`)
  }
  
  return result
}

// 使用示例
const result = measurePerformance('calculate', () => {
  return bridge.calculate(demands)
})
```
