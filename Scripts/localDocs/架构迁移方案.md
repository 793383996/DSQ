# 戴森球计划计算工具架构现代化迁移方案 (Web 专用版)

---

## 0. 核心原则：稳定第一

* **尊重遗留逻辑**：严禁在 UI 迁移过程中修改 `blueprint.js` 中的核心位运算、Base64 处理及 MD5 校验逻辑。这些代码视为“黑盒”，必须保持二进制级的一致性。
* **最小化侵入**：仅在必需处进行模块化包装，严禁“顺手清理”历史遗留但运行正常的代码。
* **先注后改**：在迁移任何涉及 `pako` 或位运算的复杂逻辑前，必须在代码中注释解释逻辑流向及安全性。
* **防御性编程**：在 TypeScript 与遗留 JS 互调边界，默认所有输入为可空（T?），并包裹 `try-catch` 防止解析异常导致 UI 崩溃。

---

## 1. 第一阶段：基础设施建设 (Infrastructure)

* **技术栈选型**：Vite + Vue 3 (Composition API) + TypeScript。
* **依赖接管**：
* 移除 `index.html` 中的 CDN 引用。
* 安装生产依赖：`pnpm add vue pinia pako`。
* 安装开发依赖：`pnpm add -D typescript vite @types/pako`。


* **消息系统平替**：封装 `cocoMessage.js` 为 Vue 插件，通过 `provide/inject` 供新组件调用，保持 API `cocoMessage.success()` 签名不变。

---

## 2. 第二阶段：数据层解耦 (Data Layer)

* **静态数据工程化**：
* 将 `data.js` 转换为 `src/core/data.json`。
* 建立 `RecipeStore` (Pinia)，在初始化时预生成 `recipeIndexByProduct` 索引，将配方查找复杂度从  降至 。


* **状态管理响应式化**：
* 将 `xqs` (需求列表)、`ig_names` (排除列表) 迁入 `useBlueprintStore`。
* 利用 `localStorage` 自动持久化用户设置，替换原有的 `jquery.cookie.min.js`。



---

## 3. 第三阶段：核心算法模块化 (Core Decoupling)

* **算法导出**：
* 将 `blueprint.js` 中的 `Blueprint` 类通过 ES Module 导出。
* **模块兼容性处理**：
```typescript
// src/core/blueprint/Blueprint.ts
import pako from 'pako'; // 接管原 Scripts/pako.js

export class Blueprint {
    /** 架构师注：严禁修改 toStr 内部的 MD5 和位移逻辑 */
    toStr() {
        // 原有逻辑保持不变...
    }
}

```




* **接口隔离**：定义 `IBlueprintRecipe` 接口规范数据结构，确保 UI 层的数据变更不会意外破坏解析器所需的字段。

---

## 4. 第四阶段：UI 组件化重构 (MVVM)

* **声明式渲染替换 DOM 操作**：
* **量产表格**：使用 `v-for` 渲染 `items` 列表，彻底移除 `index.html` 中的 `$(...).load()` 和字符串拼接逻辑。
* **交互适配**：将 `f_add()`、`f_reset()` 等全局函数迁移为组件内部的 `actions`。


* **增量组件拆分**：
* `BlueprintHeader.vue`：控制每分钟产量及基础选项。
* `CalculatorTable.vue`：核心量产计算展示区。
* `SettingDrawer.vue`：折叠式高级参数设置面板。



---

## 5. 第五阶段：性能与卫生规范 (Performance)

* **并发安全与异步化**：
* 由于 `toStr()` 涉及大量循环与压缩，将其逻辑封装在异步任务中，避免阻塞主线程（>16ms）导致页面掉帧。


* **资源指纹管理**：
* Base64 图标通过 Vite 的静态资源管道处理，利用浏览器缓存机制减少重复解析开销。


* **组件清理**：
* 在 `onUnmounted` 生命周期中显式销毁所有计时器，防止因遗留的全局监听导致的内存泄漏。
