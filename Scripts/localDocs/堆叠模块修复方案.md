## 1. 问题背景

### 问题描述

堆叠功能上线后表现异常：
- **预期**：60min产出，分4层，每层15个设备，总产能60min
- **实际**：60min产出，分4层，但产出只有14min（约1/4）

### 影响范围

所有使用堆叠功能（stackLayers > 1）的蓝图生成均受影响。

## 2. 现有错误实现分析

### 2.1 代码位置概览

| 文件 | 行号 | 方法 | 问题 |
|------|------|------|------|
| `blueprint.js` | L2052-2060 | `init()` | 过早缩减building.num |
| `blueprint.js` | L2354-2382 | `generateConveyorBelts()` | rate放大逻辑无法弥补num缩减 |
| `blueprint.js` | L2098-2227 | `cloneToStackLayers()` | 设计思路正确，但num已缩减 |

### 2.2 现有流程（错误）

```

init()                              ← 问题1: num被缩减
  subRecipe.building.num = ceil(60/4) = 15  ❌
  ↓

  高层分拣器引用z=0传送带
  但只有15个设备在工作          ❌产能=15min
```

**结果：** 总产能 = 15min（只有1/4）

### 3.1 核心设计原则

```
核心洞察：
- 分拣器分散到4层（每层15个）
- 传送带只在z=0层（完整网络，连接全部60个设备）
- 高层分拣器通过outputObjIdx/inputObjIdx引用z=0的传送带节点
- 设备分散摆放，但都连到z=0的传送带网络
```


## 4. 核心问题定位

### 4.1 问题1: init()中过早缩减num

**代码位置:** `blueprint.js` L2052-2060

```javascript
// 现有错误代码
if (this.config.stackLayers > 1) {
  for (let subRecipe of this.recipe.subRecipes) {
    if (subRecipe.building) {
      subRecipe.building.num = Math.ceil(
        subRecipe.building.num / this.config.stackLayers
      );
    }
  }
}
```

**问题分析:**
- 这段代码在堆叠模式下**过早缩减**了building.num
- 导致后续所有流程只处理1/N的设备数量
- 即使后面有rate放大逻辑，也无法弥补设备数量减少的根本问题

**修复方案:**
- **方案A**: 添加守卫条件，只在stackLayers > 1时跳过缩减
- **方案B**: 完全移除这段代码，让num保持完整值

**推荐方案A**: 最小修改，风险可控

### 4.2 问题2: generateConveyorBelts()的rate放大逻辑

**代码位置:** `blueprint.js` L2354-2382

```javascript
// 现有代码 - 试图用rate放大弥补num缩减
if (stackLayers > 1) {
  for (let key in itemSummary) {
    itemSummary[key].rate *= stackLayers;
    // ...
  }
}
```

**问题分析:**
- 这是**补偿逻辑**，试图弥补num缩减的问题
- 但传送带数量、连接关系等无法通过简单的rate放大来解决
- 治标不治本

**修复方案:**
- num缩减问题修复后，这段rate放大逻辑应**完全移除**
- 因为此时itemSummary.rate已经反映完整产能

### 4.3 问题3: cloneToStackLayers()的分拣器分配

**代码位置:** `blueprint.js` L2098-2227

**现有设计（基本正确）:**
- 跳过Lab、传送带、喷涂机
- 只克隆分拣器到高层
- 高层分拣器的inputObjIdx指向地基（当base.inputObjIdx === -1时）

**需要调整:**
- 当base.inputObjIdx !== -1时，高层分拣器应该**引用z=0的传送带节点**
- 而不是通过indexMap重映射（因为传送带不克隆）

## 5. 详细修改方案

### 5.1 修改1: init() - 跳过num缩减

**文件:** `blueprint.js`

**位置:** L2052-2060

**修改前:**
```javascript
if (this.config.stackLayers > 1) {
  for (let subRecipe of this.recipe.subRecipes) {
    if (subRecipe.building) {
      subRecipe.building.num = Math.ceil(
        subRecipe.building.num / this.config.stackLayers
      );
    }
  }
}
```

**修改后:**
```javascript
// 堆叠模式下不缩减num，保持完整产能
// num缩减逻辑移除，改为在cloneToStackLayers()中分散设备
if (false) { // 禁用num缩减
  for (let subRecipe of this.recipe.subRecipes) {
    if (subRecipe.building) {
      subRecipe.building.num = Math.ceil(
        subRecipe.building.num / this.config.stackLayers
      );
    }
  }
}
```

**或者更简洁的方案（推荐）:**

```javascript
// 堆叠模式下不缩减num，保持完整产能
// 设备分散在cloneToStackLayers()中处理
```

### 5.2 修改2: generateConveyorBelts() - 移除rate放大

**文件:** `blueprint.js`

**位置:** L2354-2382

**修改前:**
```javascript
const stackLayers = this.config.stackLayers || 1;
if (stackLayers > 1) {
  for (let key in itemSummary) {
    itemSummary[key].rate *= stackLayers;
    if (itemSummary[key].inputRate !== undefined) {
      itemSummary[key].inputRate *= stackLayers;
    }
  }
  // ... 分拣器rate放大
}
```

**修改后:**
```javascript
// 移除rate放大逻辑
// 堆叠模式下保持itemSummary.rate反映完整产能
```

### 5.3 修改3: cloneToStackLayers() - 调整分拣器引用

**文件:** `blueprint.js`

**位置:** L2195-2210

**现有代码逻辑:**
```javascript
if (base.inputObjIdx === -1) {
  clone.inputObjIdx = foundationIndex;
} else {
  // indexMap重映射
  if (indexMap.has(base.inputObjIdx)) {
    clone.inputObjIdx = indexMap.get(base.inputObjIdx);
  } else {
    clone.inputObjIdx = base.inputObjIdx;
  }
}
```

**需要调整:**
- 当base是分拣器且base.inputObjIdx !== -1时
- clone.inputObjIdx应该**保持z=0传送带的index**（不通过indexMap）
- 因为传送带不克隆，高层分拣器直接引用z=0传送带

## 7. 影响分析

### 7.1 正面影响

1. **产能恢复**: 堆叠功能恢复正常工作，总产能=原始产能
2. **逻辑清晰**: "先完整生成，再分散摆放"的流程更易理解
3. **兼容性**: 现有非堆叠模式完全不受影响

### 7.2 潜在风险

1. **传送带容量**: z=0层传送带需要承载4层的流量
   - 需验证：现有传送带容量设计是否足够
   - 潜在问题：如果60min需要多条传送带并联，分散后可能需要调整

2. **分拣器连接**: 高层分拣器引用z=0传送带
   - 需验证：游戏内实际连接是否正确
   - 潜在问题：DSP是否支持跨层引用传送带节点

3. **性能影响**: 生成更多设备可能影响生成时间
   - 60个设备 vs 15个设备
   - 预期影响：生成时间增加约4倍（可接受）

### 7.3 兼容性影响

| 场景 | 修改前 | 修改后 | 兼容性 |
|------|--------|--------|--------|
| stackLayers=1 | 正常工作 | 正常工作 | ✅ |
| stackLayers=2 | 产能=1/2 | 产能=完整 | ✅ 需验证 |
| stackLayers=3 | 产能=1/3 | 产能=完整 | ✅ 需验证 |
| stackLayers=4 | 产能=1/4 | 产能=完整 | ✅ 需验证 |

## 9. 总结

### 9.1 核心变更

1. **移除init()中的num缩减逻辑**
2. **移除generateConveyorBelts()中的rate放大逻辑**
3. **调整cloneToStackLayers()的分拣器引用逻辑**

### 9.2 设计原则

- **先完整生成，再分散摆放**
- 分拣器分散到多层
- 传送带只在z=0层
- 高层分拣器直接引用z=0传送带

### 9.3 预期效果

- ✅ 堆叠功能恢复正常
- ✅ 总产能 = 原始产能（不缩减）
- ✅ 占地面积减少为1/N
- ✅ 向后兼容stackLayers=1的场景
