# 重构后部署方案

## 1. 部署架构对比

### 1.1 重构前部署流程

```
开发环境 → git push → GitHub main分支 → 服务器监听 → 自动部署
                ↓
         直接部署源码
         (index.html + Scripts/ + img/ + quote/)
```

**特点**：
- 纯静态HTML项目，无需构建
- main分支直接包含可部署资源
- 服务器拉取源码即可运行

### 1.2 重构后部署流程

```
开发环境 → git push → GitHub main分支 → CI触发 → npm run build → 部署dist/
                ↓
         源码 (src/ + Scripts/ + 配置文件)
                ↓
         构建产物 (dist/)
                ↓
         部署到服务器
```

**特点**：
- Vue 3 + TypeScript + Vite 项目
- 需要构建步骤生成静态资源
- 部署内容为构建产物 `dist/`

## 2. 部署方案选择

### 方案A：源码分支 + CI构建（推荐）

```
main分支：源码（src/、Scripts/、package.json等）
         ↓ CI触发
构建产物：临时生成，部署后丢弃
```

**优点**：
- 仓库体积小，历史清晰
- 符合现代前端工程规范
- 便于代码审查和回滚

**缺点**：
- 需要配置CI/CD流程
- 服务器需要支持CI构建或接收构建产物

### 方案B：双分支模式

```
main分支：源码（开发用）
dist分支：构建产物（部署用）
```

**优点**：
- 部署分支独立，回滚方便
- 兼容原有服务器监听机制

**缺点**：
- 需要维护两个分支
- 仓库体积增大

### 方案C：单分支包含构建产物

```
main分支：源码 + dist/目录
```

**优点**：
- 最简单，无需CI配置
- 兼容原有部署流程

**缺点**：
- 仓库体积大
- 提交历史混乱
- 不符合最佳实践

## 3. 推荐方案：方案A + GitHub Actions

### 3.1 GitHub Actions 配置

创建文件 `.github/workflows/deploy.yml`：

```yaml
name: Build and Deploy

on:
  push:
    branches: [main]
  workflow_dispatch:

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    
    steps:
      - name: Checkout
        uses: actions/checkout@v4
        
      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'
          
      - name: Install dependencies
        run: npm ci
        
      - name: Build
        run: npm run build
        
      - name: Deploy to Server
        uses: easingthemes/ssh-deploy@main
        with:
          SSH_PRIVATE_KEY: ${{ secrets.SSH_PRIVATE_KEY }}
          REMOTE_HOST: ${{ secrets.REMOTE_HOST }}
          REMOTE_USER: ${{ secrets.REMOTE_USER }}
          SOURCE: dist/
          TARGET: /var/www/dsq/
```

### 3.2 服务器配置

服务器需要：
1. SSH访问权限
2. Web服务器（Nginx/Apache）指向部署目录
3. 配置GitHub Secrets

### 3.3 Nginx 配置示例

```nginx
server {
    listen 80;
    server_name your-domain.com;
    root /var/www/dsq;
    index index.html;
    
    location / {
        try_files $uri $uri/ /index.html;
    }
    
    location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff|woff2)$ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }
}
```

## 4. 兼容原有部署方式（方案B）

如果服务器监听机制无法修改，采用双分支模式：

### 4.1 分支结构

| 分支 | 内容 | 用途 |
|------|------|------|
| main | 源码 | 开发、代码审查 |
| dist | 构建产物 | 部署 |

### 4.2 自动同步脚本

创建 `scripts/deploy.sh`：

```bash
#!/bin/bash
set -e

echo "Building project..."
npm run build

echo "Deploying to dist branch..."
cd dist
git init
git add -A
git commit -m "Deploy: $(date '+%Y-%m-%d %H:%M:%S')"
git push -f git@github.com:username/DSQ.git main:dist

echo "Deploy completed!"
```

### 4.3 package.json 添加脚本

```json
{
  "scripts": {
    "deploy": "bash scripts/deploy.sh"
  }
}
```

## 5. 构建产物说明

### 5.1 构建命令

```bash
npm install        # 安装依赖
npm run build      # 构建（vue-tsc类型检查 + vite build）
```

### 5.2 构建产物结构

```
dist/
├── index.html           # 入口HTML
├── assets/
│   ├── index-[hash].js  # 主JS包
│   ├── index-[hash].css # 主CSS包
│   └── [hash].js        # 其他chunk
└── [其他静态资源]
```

### 5.3 需要复制的静态资源

构建时需将以下资源复制到 `dist/`：

| 源路径 | 目标路径 | 说明 |
|--------|----------|------|
| Scripts/data.json | dist/Scripts/ | 游戏图标数据 |
| img/ | dist/img/ | 图片资源 |
| favicon.ico | dist/ | 网站图标 |

### 5.4 vite.config.ts 配置静态资源复制

```typescript
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import { resolve } from 'path'

export default defineConfig({
  plugins: [vue()],
  resolve: {
    alias: {
      '@': resolve(__dirname, 'src')
    }
  },
  server: {
    port: 3000,
    host: true
  },
  build: {
    target: 'esnext',
    outDir: 'dist',
    assetsDir: 'assets',
    rollupOptions: {
      output: {
        manualChunks: {
          'vendor': ['vue', 'pinia'],
          'legacy': ['jquery', 'pako']
        }
      }
    }
  },
  optimizeDeps: {
    include: ['vue', 'pinia']
  }
})
```

## 7. 迁移步骤

### 7.1 准备阶段

1. 备份当前main分支
2. 创建 `backup` 分支保存原始代码
3. 确认所有功能已迁移完成

### 7.2 配置CI/CD

1. 添加 `.github/workflows/deploy.yml`
2. 配置 GitHub Secrets
3. 测试构建流程

### 7.3 切换部署

1. 合并重构代码到main分支
2. 触发CI构建
3. 验证部署结果

### 7.4 清理工作

1. 删除 `backup` 分支（确认无问题后）
2. 更新 README.md 部署说明
3. 通知团队成员新的开发流程

## 11. Vercel 部署方案（推荐）

### 11.1 Vercel 简介

Vercel 是一个现代化的前端部署平台，专为现代前端框架优化，具有以下特点：

| 特性 | 说明 |
|------|------|
| 零配置构建 | 自动检测 Vite/Vue 项目，无需配置 CI |
| Git 集成 | 连接 GitHub 后，push 自动触发部署 |
| Preview 部署 | 非 main 分支自动生成预览 URL |
| Production 部署 | main 分支自动部署到生产环境 |
| 全球 CDN | 自动分发到全球边缘节点 |
| 免费额度 | 个人项目免费，足够中小型项目使用 |

### 11.2 Vercel 部署流程

```
开发环境 → git push → GitHub main分支 → Vercel监听 → 自动构建 → 部署
                ↓
         源码 (src/ + Scripts/ + 配置文件)
                ↓
         Vercel 自动执行 npm run build
                ↓
         构建产物自动部署到 CDN
```

**核心优势**：
- **无需双分支**：Vercel 自动构建，main 分支只需源码
- **无需配置 CI**：Vercel 内置构建流程
- **无需服务器**：Vercel 提供托管服务

### 11.3 Vercel 部署配置

#### 步骤1：连接 GitHub 仓库

1. 登录 [Vercel](https://vercel.com)
2. 点击 "Add New Project"
3. 选择 GitHub 仓库 `DSQ`
4. Vercel 自动检测到 Vite 项目

#### 步骤2：配置构建设置

Vercel 会自动识别 Vite 项目，默认配置如下：

| 配置项 | 值 |
|--------|-----|
| Framework Preset | Vite |
| Build Command | `npm run build` |
| Output Directory | `dist` |
| Install Command | `npm install` |

#### 步骤3：配置静态资源复制

由于项目需要 `Scripts/data.json` 和 `img/` 目录，需要配置复制：

创建 `vercel.json`：

```json
{
  "buildCommand": "npm run build && node scripts/copy-static.js",
  "outputDirectory": "dist",
  "framework": "vite",
  "rewrites": [
    { "source": "/(.*)", "destination": "/index.html" }
  ],
  "headers": [
    {
      "source": "/assets/(.*)",
      "headers": [
        { "key": "Cache-Control", "value": "public, max-age=31536000, immutable" }
      ]
    }
  ]
}
```

创建 `scripts/copy-static.js`：

```javascript
import { cpSync, mkdirSync } from 'fs'
import { resolve, dirname } from 'path'
import { fileURLToPath } from 'url'

const __dirname = dirname(fileURLToPath(import.meta.url))
const root = resolve(__dirname, '..')
const dist = resolve(root, 'dist')

mkdirSync(resolve(dist, 'Scripts'), { recursive: true })
mkdirSync(resolve(dist, 'img'), { recursive: true })

cpSync(resolve(root, 'Scripts/data.json'), resolve(dist, 'Scripts/data.json'))
cpSync(resolve(root, 'img'), resolve(dist, 'img'), { recursive: true })
cpSync(resolve(root, 'favicon.ico'), resolve(dist, 'favicon.ico'))

console.log('Static assets copied successfully!')
```

#### 步骤4：配置 SPA 路由

创建 `vercel.json` 添加 SPA 路由支持：

```json
{
  "rewrites": [
    { "source": "/(.*)", "destination": "/index.html" }
  ]
}
```

### 11.4 分支部署策略

Vercel 支持多分支部署，无需手动维护双分支：

| 分支 | 部署环境 | URL 格式 |
|------|----------|----------|
| main | Production | `https://your-project.vercel.app` |
| develop | Preview | `https://dsq-git-develop-username.vercel.app` |
| feature/* | Preview | `https://dsq-git-feature-xxx-username.vercel.app` |

**工作流程**：

```
开发分支 (feature/*) → Push → Preview 部署 → 测试验证
        ↓
合并到 develop → Push → Preview 部署 → 集成测试
        ↓
合并到 main → Push → Production 部署 → 生产发布
```

### 11.5 Vercel vs GitHub Actions 对比

| 维度 | Vercel | GitHub Actions + 服务器 |
|------|--------|------------------------|
| 配置复杂度 | 低（零配置） | 高（需配置 workflow） |
| 服务器成本 | 免费（个人项目） | 需自备服务器 |
| CDN | 自动全球 CDN | 需额外配置 |
| 预览部署 | 自动（每个分支） | 需手动配置 |
| 构建时间 | Vercel 云端构建 | GitHub Actions 构建 |
| 自定义域名 | 支持 | 支持 |
| 回滚 | 一键回滚 | 需重新部署 |

### 11.6 推荐方案：Vercel 单分支部署

**最终推荐**：使用 Vercel 部署，无需双分支。

```
main 分支：源码（开发用）
    ↓ Vercel 自动监听
自动构建：npm run build
    ↓
自动部署：Production 环境
```

**优势**：
1. **零运维**：无需维护服务器和 CI 配置
2. **零成本**：个人项目免费
3. **高效**：push 即部署，无需手动操作
4. **安全**：自动 HTTPS，全球 CDN

## 12. 最终部署方案总结

### 12.1 方案对比

| 方案 | 适用场景 | 复杂度 | 成本 |
|------|----------|--------|------|
| Vercel（推荐） | 个人/小团队项目 | 低 | 免费 |
| GitHub Actions + 服务器 | 企业项目、需自定义 | 中 | 服务器费用 |
| 双分支模式 | 兼容旧部署流程 | 高 | 无额外费用 |

### 12.2 推荐决策树

```
是否需要自有服务器？
├── 是 → GitHub Actions + 服务器部署
└── 否 → 是否需要完全控制构建流程？
         ├── 是 → GitHub Actions + Vercel
         └── 否 → Vercel 自动构建（推荐）
```

### 12.3 最终推荐

- main 分支：源码
